## 镜头 3：第二步 — 发需求给豆包，生成完整可运行源码（50-100 秒）

**画面**：
1. 把豆包上一条输出的内容全部复制（包含需求 + 题库）
2. 在同一个对话窗口继续输入新提示词，粘贴刚刚的需求
3. 等待豆包输出完整源码

**给豆包提示词（直接复制）**：

```
根据你上面给我的需求文档和 30 道内置题库，帮我直接生成完整的可运行单页网页源码。

技术要求：
- 纯前端实现（HTML + CSS + JavaScript），一个文件搞定
- 不需要后端、不需要数据库、不需要登录
- 卡片正面显示题目，点击整张卡片翻转显示答案，翻转动画要流畅，用 CSS 3D transform 实现
- 顶部有分类标签切换（全部 / 计算机网络 / 操作系统 / 数据结构 / 数据库）
- 每张卡片下方有「已掌握 ✓」和「再复习 ↩」两个按钮
- 右上角显示当前分类的掌握进度（环形进度条或百分比）
- 用 localStorage 持久化掌握状态，刷新页面不丢失
- 底部加一个「随机挑战」按钮，点击后随机抽一题，模拟面试场景
- UI 风格：深色主题，卡片风格简洁高级，适合程序员审美，类似 LeetCode 暗色模式
- 代码完整可直接运行，不需要我再做任何修改
- 先列出你将包含的完整功能清单，再给出全部源码
```

**口播台词**：
> 现在把刚才豆包自己写的需求原封不动发回去，让它直接出源码。注意我的提示词里把技术要求写得非常具体——CSS 3D 翻转、分类切换、进度统计、localStorage 持久化、深色主题，一次性说清楚，代码就不用返工。

**操作**：等待豆包输出完整代码。如果代码太长被截断，说一句「继续」让它接着输出。

**预期画面效果**：豆包先输出「将包含的功能清单」（约 5-10 行），然后输出完整 HTML 文件源码（大概 400-600 行），镜头加速播放或跳过中间部分，展示代码的关键段落（翻转动画的 CSS、localStorage 逻辑、卡片数据结构）。

# 补充说明

## 拍摄注意事项

1. **录屏清晰度**：建议 1080P 以上，代码字体调大（VS Code 内 Ctrl+Plus），保证手机端也能看清
2. **豆包响应时间**：生成代码可能需要 30-60 秒，拍摄时可以加速或剪辑跳过等待
3. **提前测试**：建议提前跑一遍流程，确保豆包输出的代码能正常运行，避免拍摄时翻车。如果某条提示词豆包输出不符合预期，可以追加一句修正指令
4. **口播节奏**：CS 博主风格可以稍微快一点，不用像教程博主那么慢，保留「理工男」的语速和语气

## 如果拍摄中遇到问题的备选方案

| 问题 | 解决 |
|------|------|
| 豆包代码太长被截断 | 输入「继续」让它接着输出 |
| UI 优化不够满意 | 截图当前的界面发给豆包（豆包支持图片输入），说「按照这个截图帮我优化 XXX」 |
| 翻转动画不流畅 | 在提示词 2 中加一句「翻转动画参考 Apple Wallet 卡片翻转效果」 |
| 题库内容太简单 | 修改提示词 1，把「30 道」改成「50 道」，或指定更细的方向如「Java 后端面试高频题」 |

## 这个视频的差异化优势

- **CS 博主专属**：非技术博主做不了这个选题，精准打击计算机/软件工程大学生群体
- **自带搜索流量**：「面试八股文」「程序员面试」是常年高频搜索词
- **工具可复用**：观众看完真的会用，不是纯娱乐内容，完播率和收藏率都会很高
- **评论互动强**：评论区一定会有人求源码、求题库、讨论面试题答案，互动数据好
